Диаграммы охватывают четыре ключевых процесса, в которых обрабатываются конфиденциальные данные: запись пациента, ведение медицинской карты, учёт анализов и оплата услуг. На каждой диаграмме показаны внешние субъекты, процессы, хранилища данных и потоки между ними, а также блоки с рекомендуемыми мерами защиты на этапе ввода данных, их обработки и хранения.

## Результаты аудита

[security_audit.md](security_audit.md) содержит список конфиденциальных данных, не учтённых во внутренних системах, десять проблемных зон в работе с данными и их сопоставление с требованиями 152-ФЗ и практиками Privacy by Design, Data Minimization, Data Lineage.

Ключевые проблемы: отсутствие ролевого разграничения доступа (только доменная аутентификация), отсутствие шифрования и аудита действий с данными, смешение данных разных категорий чувствительности в общих хранилищах, ручное дублирование платёжных данных, отсутствие процесса удаления данных по запросу пациента.

## План защиты данных

[data_protection_plan.md](data_protection_plan.md) содержит:

- список данных для защиты с указанием способа защиты (шифрование, обфускация, обезличивание, маскирование) для каждой категории;
- механизм тегирования данных (`PII`, `SPECIAL_CATEGORY`, `PAYMENT`, `HR`, `INTERNAL`) с инструментами для его реализации (data catalog, DLP-система, CI-проверка релиза);
- список инструментов и мер для обеспечения конфиденциальности данных в потоках: шифрование at rest и in transit, RBAC/ABAC, обезличивание для аналитики, маскирование в интерфейсах, журналирование и аудит, единый источник данных для платежей, регламент удаления данных по запросу пациента.
